# SchoolLive 2.0

Платформа прямых эфиров и архива мероприятий Шуваловской школы № 1448. Администрация ведёт эфир с телефона прямо в браузере, зрители смотрят без входа, после эфира запись сама появляется в архиве.

## Что внутри

```
Телефон (браузер, /studio)          Зрители (браузер)
  камера → H.264, 3 слоя             WebRTC, задержка < 1 с
  (1080p / 540p / 270p)                    ▲  каждому — свой слой
        │ WHIP                              │  по его каналу
        ▼                                   │
┌───────────── server (Rust) ───────────────┴──────┐
│ HTTP API · вход по коду · SSE                     │
│ SFU на str0m: пересылка без перекодирования       │
│ запись в .mkv → ffmpeg → HLS-архив 1080/720/480   │
│ SQLite                                            │
└───────────────────────────────────────────────────┘
Caddy: HTTPS, сайт, файлы архива
```

- **Быстрый старт.** Зритель видит картинку через ~0,2 с после запуска плеера и через ~0,55 с после открытия страницы (локально, из автотеста). Сервер сразу запрашивает у телефона ключевой кадр и начинает с того слоя, кадр которого пришёл первым.
- **Без лагов.** Телефон кодирует три качества сразу, сервер выбирает для каждого зрителя слой по его каналу (TWCC/BWE). Общий интернет-канал школы ограничен лимитом `EGRESS_LIMIT_MBPS`; зрители в школьной сети в лимит не входят.
- **Надёжность.** При смене Wi-Fi на 4G телефон переподключается в тот же эфир, зрители не отключаются. Эфир можно перехватить с другого устройства. Записи переживают падение сервера.
- **Архив.** Если эфир шёл одним куском в H.264, запись готова через секунды: видео копируется в HLS без перекодирования. Затем в фоне добавляются 720p и 480p.

## Структура

| Путь | Что там |
|---|---|
| `server/` | Rust: axum, str0m, sqlx/SQLite |
| `server/src/sfu/` | медиасервер: комнаты, simulcast, выбор слоёв |
| `server/src/media/` | запись (Matroska), обработка ffmpeg |
| `web/` | React 19 + TypeScript + Vite |
| `web/src/live/` | WebRTC-клиенты: `whep.ts` (зритель), `whip.ts` (студия) |
| `web/e2e/` | сквозной тест Playwright |
| `deploy/`, `compose.yaml` | Docker-образы и Caddy |
| `docs/` | установка и памятка для администрации |

## Разработка

Нужны Rust (stable), Node 24+, ffmpeg.

```bash
./scripts/dev-server.sh          # API + медиасервер на :8080, код администрации: school1448
npm --prefix web install
npm --prefix web run dev         # сайт на http://localhost:5173
```

Проверка с телефона в той же Wi-Fi сети (камере нужен HTTPS):

```bash
./scripts/phone-test.sh          # https://<IP Mac>:5443 и сертификат http://<IP Mac>:5480/schoollive-ca.crt
```

Скрипт создаёт в `.certs/` локальный центр сертификации, который подтверждает только адреса локальной сети. Его сертификат нужно один раз установить на телефон и включить доверие. Шаги для iPhone те же, что в разделе «Тест в локальной сети» в [docs/УСТАНОВКА.md](docs/УСТАНОВКА.md).

Тесты:

```bash
cargo test                                    # логика SFU, запись, вход
npm --prefix web run e2e                      # эфир → просмотр → архив (нужен Google Chrome)
```

Сквозной тест запускает «телефон» на фейковой камере Chrome и второго зрителя. Он проверяет время до первого кадра, переключение качества, перехват эфира с другого устройства и появление записи в архиве.

Проверка Docker-образов на Mac. В Docker Desktop нет настоящей host-сети, поэтому порты публикуются отдельным файлом. В `.env` укажите `CADDYFILE=Caddyfile.local`, `LOCAL_HTTPS_HOST=localhost`, `ALLOWED_ORIGINS=https://localhost:8443`, `MEDIA_LAN_IP=<IP Mac>`, `MEDIA_PORT=18189`.

```bash
docker compose -p schoollive-test -f compose.yaml -f deploy/compose.macos.yaml up -d --build
BASE_URL=https://localhost:8443 npm --prefix web run e2e
docker compose -p schoollive-test -f compose.yaml -f deploy/compose.macos.yaml down -v
```
