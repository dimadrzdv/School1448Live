# Установка на сервер в школе

## 1. Что нужно

- **Компьютер-сервер**: Linux (Ubuntu 24.04 или Debian 13), 4 ядра, 8 ГБ памяти, SSD от 500 ГБ.
  - Живого перекодирования нет, поэтому процессор нагружает только обработка архива после эфира.
  - Час записи 1080p занимает 2–2,5 ГБ, лестница качеств — ещё около 1 ГБ.
- **Подключение к школьной сети кабелем**, лучше гигабитным.
- **Белый статический IP школы** (уточните у провайдера или в ИТ-службе) и доступ к роутеру для проброса портов.
- **Домен**, например `live.sch1448.ru`, с DNS-записью `A`, указывающей на белый IP.
- **Docker** с Compose v2: https://docs.docker.com/engine/install/

> Если школьная сеть ДОНМ не позволяет пробросить порты, всё то же самое ставится на арендованный VPS. Инструкция не меняется, только `MEDIA_LAN_IP` = IP VPS, `MEDIA_PUBLIC_IP` оставить пустым, а `MAX_VIEWERS_PER_IP=0`: зрители из школы приходят на VPS с одного IP школы.

## 2. Порты на роутере

Пробросьте на IP сервера в школьной сети:

| Порт | Протокол | Зачем |
|---|---|---|
| 80 | TCP | выпуск сертификата Let's Encrypt, редирект на HTTPS |
| 443 | TCP | сайт и API |
| 8189 | **UDP и TCP** | видео WebRTC (TCP — для сетей, где UDP закрыт) |

Если на сервере включён файрвол:

```bash
sudo ufw allow 80,443/tcp
sudo ufw allow 8189
```

## 3. Настройка

```bash
git clone <репозиторий> schoollive && cd schoollive
cp .env.example .env
```

Заполните `.env`:

- `DOMAIN` и `ALLOWED_ORIGINS` — ваш домен.
- `MEDIA_LAN_IP` — IP сервера в школьной сети (`ip -4 addr`).
- `MEDIA_PUBLIC_IP` — белый IP школы.
- `EGRESS_LIMIT_MBPS` — около 70% **исходящей** скорости интернета школы. Например, при 300 Мбит/с укажите 200.
  - Зрители вне школы делят этот канал.
  - Когда их много, сервер понижает качество самым «тяжёлым» из них, чтобы ни у кого не было лагов.
  - Зрители в школьной сети в лимит не входят.
- `MAX_VIEWERS_PER_IP` — сколько зрителей могут смотреть с одного внешнего IP (по умолчанию 20, `0` — без лимита). Адреса школьной сети не ограничиваются.

Секретный код администрации (не короче 6 символов):

```bash
docker compose build server
echo -n 'придумайте-код' | docker compose run --rm -T server hash-code
```

Команда выведет строку `ADMIN_CODE_HASH='...'`. Замените ею строку в `.env`. Сам код нигде не хранится. Чтобы сменить код, повторите команду и перезапустите сервер.

## 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f server
```

В логе должно быть `медиасервер запущен … lan=<IP сервера> public=<белый IP>`. Откройте `https://ваш-домен`, затем `https://ваш-домен/admin` и введите код.

## 5. Проверка

1. Откройте сайт с телефона через мобильный интернет (не школьный Wi-Fi). Так проверяется доступ снаружи.
2. Создайте пробный эфир в панели администрации, нажмите «Студия», затем «В эфир».
3. Откройте эфир на другом устройстве. Картинка должна появиться меньше чем за секунду.
4. Завершите эфир. Через полминуты запись появится в архиве.

## Внутри школы: зрители и hairpin NAT

- **Видео.** Зрители в школьной сети получают видео напрямую по локальной сети (сервер объявляет свой LAN-адрес), интернет-канал на них не тратится.
- **Сайт по домену изнутри школы.** Роутер должен поддерживать hairpin NAT (NAT loopback). Если не поддерживает, настройте на школьном DNS запись `домен → MEDIA_LAN_IP` (split-DNS).

## Тест в локальной сети без домена

Камера в браузере работает только по HTTPS. Для проверки до появления домена есть режим HTTPS по IP с собственным сертификатом.

```dotenv
CADDYFILE=Caddyfile.local
LOCAL_HTTPS_HOST=192.168.1.10
ALLOWED_ORIGINS=https://192.168.1.10
```

```bash
docker compose up -d --build
```

На iPhone:

1. В Safari откройте `http://192.168.1.10/schoollive-ca.crt` и разрешите загрузку профиля.
2. В **Настройки → Основные → VPN и управление устройством** установите профиль **Caddy Local Authority**.
3. В **Основные → Об этом устройстве → Доверие сертификатам** включите доверие для него.
4. Откройте `https://192.168.1.10`.

Android устанавливает сертификат через **Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС**.

Для работы с доменом верните `CADDYFILE=Caddyfile`.

## Обновление

```bash
git pull
docker compose up -d --build
```

Обновляйте, когда нет эфира. При остановке сервер корректно завершает эфиры и закрывает записи, они обработаются автоматически.

## Резервная копия

Все данные (база, архив) лежат в томе `schoollive_data`:

```bash
docker run --rm -v schoollive_data:/data -v "$PWD":/backup debian:trixie-slim \
  tar czf /backup/schoollive-$(date +%F).tar.gz -C /data .
```

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Сайт открывается, а видео нет («Подключаемся…» не проходит) | Проброшен ли порт 8189 **UDP и TCP**; верны ли `MEDIA_LAN_IP` и `MEDIA_PUBLIC_IP` (см. строку `медиасервер запущен` в логе) |
| Изнутри школы сайт по домену не открывается | hairpin NAT или split-DNS, см. выше |
| Студия пишет «Камера работает только по HTTPS» | Сайт открыт по `http://` или по IP без режима `Caddyfile.local` |
| Не выпускается сертификат | Порт 80 проброшен? DNS-запись `A` указывает на белый IP? |
| Зритель видит «Из вашей сети смотрят слишком много зрителей» | За одним внешним IP больше `MAX_VIEWERS_PER_IP` зрителей (сервер на VPS, общий Wi-Fi вне школы). Увеличьте значение или поставьте `0`, затем `docker compose up -d`. В логе это строки «лимит зрителей с одного адреса» |
| Запись долго «Обработка…» | `docker compose logs server`, строки «обработка записи» |
